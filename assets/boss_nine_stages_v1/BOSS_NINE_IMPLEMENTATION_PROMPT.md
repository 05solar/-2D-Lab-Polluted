# 9단계 보스전 확장 작업 지시

이 문서 전체를 구현 AI에게 전달한다. LibGDX / Java 8, core + lwjgl3 프로젝트에 적용한다. 실제 코드·에셋 경로·기존 문서를 먼저 확인하고, 설명만 작성하지 말고 실행되는 기능까지 완성하라. 기존 1-1 보스전, 본부·일반 연구소·저장·강화·스킬 동작을 보존한다. 이 에셋 팩은 아트/데이터 자료이며 실제 프로젝트에 적용·검증된 코드가 아니다.

## 1. 먼저 확인하고 보존할 것

- ARCHITECTURE.md, GAME_RULES.md, ROADMAP.md, TEST_PLAN.md, PROGRESS.md와 현재 보스 구현을 읽는다. 실제 package 이름을 유지한다.
- 본부 메인 컴퓨터 → 단계 선택 → 입장 페이드 → 보스전 → 보상 확정 → 본부 복귀의 실제 호출 경로를 확인한다. 별도 샘플 화면에만 구현하지 않는다.
- 기존 1-1의 HP·패턴·보상·저장 계약은 회귀 기준으로 삼는다. 표시명은 ‘폐기물 변이체’로 통일할 수 있지만 이미 연결된 보스 ID·저장 키·아이템 ID를 임의로 바꾸지 않는다. 기존 C-01 원화는 1-1로 재사용할 수 있다.
- **현재 플레이어 스킬 범위는 그대로 유지한다.** 사거리·반경·부채꼴 각도·돌진 거리·판정 두께를 현재 데이터에서 기록한 뒤 수정 전후 비교한다. 보스 크기에 맞춰 플레이어 스킬 범위까지 확대하지 않는다.
- F 돌진, Q 회복, 1·2·3 추가 스킬, R 가방, H 귀환, Space 상호작용의 기존 배정을 유지한다. 보스 선택창이 키 입력을 소비하면 월드 상호작용/공격까지 전파하지 않는다.

## 2. 단계와 외형

| 단계 | 보스 | 주요 패턴 |
|---|---|---|
| 1-1 | 폐기물 변이체 | 투척·짧은 돌진; 기존 추가 패턴은 회귀 기준에 따라 유지 |
| 1-2 | 냉각관 거수 | 냉기 부채꼴·빙결 장판 |
| 1-3 | 배양낭 군체 | 산성 투척·포자 지대 |
| 1-4 | 보안 제압 기체 | 조준 사격·회전 레이저 |
| 1-5 | 신경 접속 표본 | 원형 충격파·지연 폭발 |
| 1-보스 | 중앙 격리실 융합체 | HP 50% 분노 전환·투척/돌진/장판의 복합 공격 |
| 2-1 | 저온실 다족 실험체 | 방향을 다시 예고하는 연속 돌진·얼음 파편 |
| 2-2 | 변이 식물 실험체 | 뿌리 구속·독성 구역 |
| 2-3 | 이동형 배양 탱크 | 이동 포격·위험 물질 누출 |

해금 순서는 표 순서대로 한 단계씩이다. ‘진행상 해금’, ‘구현 준비 완료’, ‘클리어’는 별도 값이다. 저장 데이터를 마이그레이션하고 기존 1-1 클리어를 잃지 않게 한다. 디버그 해금은 배포 설정과 분리한다.

## 3. 보스 크기: 표시와 판정을 분리

- 새 시트는 256×256 고정 셀, 발밑 기준점은 왼쪽 위 좌표 [128,224]. 전 프레임 같은 배율과 기준점을 사용한다. 프레임마다 trim·중앙 재정렬·크기 재계산을 금지한다.
- 일반 보스의 기본 drawSize는 월드 8×8타일, 1-보스는 9.5×9.5타일을 시작값으로 한다. 실제 불투명 몸체 폭은 대략 5~6타일이 되도록 확인한다. 기존 플레이어가 1타일 전후라면 확실한 크기 차이가 나야 한다. 해상도와 카메라 줌으로만 크게 보이게 하지 않는다.
- 바닥 이동 충돌, 공격을 받는 hurtbox, 접촉 피해, 패턴 범위는 별도 데이터다. 큰 투명 캔버스 전체를 충돌 사각형으로 쓰지 않는다. 촉수·케이블·발광 파티클 전체를 벽처럼 막지 않는다.
- 에셋의 겉몸통과 hurtbox가 납득 가능하게 겹치도록 디버그 오버레이로 조정한다. 플레이어가 다리 사이/몸통을 관통하거나 보이지 않는 먼 곳에서 막히면 실패다. 충돌체를 작게만 해서 억지 해결하지 않는다.
- 근접 공격은 플레이어와 보스 중심 간 거리만 비교하지 말고, 실제 공격 도형과 보스 hurtbox의 겹침으로 판정한다. 플레이어 사거리 자체는 늘리지 않는다.
- 전투 공간은 데이터 예시의 36×28~52×40을 출발점으로 한다. 실제 보스 몸체·플레이어 충돌 폭을 고려해 확장한다. 모든 이동 가능 통로에 보스가 들어가야 하는 것은 아니지만, 돌진 경로와 회복 위치에 보스가 끼면 안 된다.
- 보스·플레이어·기둥은 발밑 Y 기준으로 자연스럽게 가려지도록 정렬한다. 상단 HP바와 좌상단 플레이어 HUD는 UI 뷰포트에 고정한다.

## 4. 공통 구조와 패턴 실행

기존 구조를 먼저 재사용한다. 순수 Java 모델에서 StageDefinition, BossDefinition, PatternDefinition, BossState/PatternController, ArenaDefinition, StageProgress, RewardReceipt를 데이터로 다룬다. 이름은 실제 프로젝트 관례를 따른다. 단계별 Screen 복사본 9개나 거대한 stageId switch문을 만들지 않는다. 렌더러는 상태와 시간에 따른 프레임을 그릴 뿐 피해/보상을 실행하지 않는다. Texture는 기존 GameAssets 생명주기로 관리한다.

상태: INTRO → IDLE/선택 → TELEGRAPH → ACTIVE → RECOVERY → 다음 패턴. DYING/CLEARED/FAILED/REWARD_PENDING은 명시적으로 처리한다. 패턴별 타깃 고정 시점, 발사 시각, 피해 시작/끝, 회복 시간을 한 전투 시계에서 읽는다. 애니메이션이 끝났다는 렌더 콜백에서 공격을 중복 발생시키지 않는다.

새 보스 시트의 행 우선 프레임: idle 0~3, telegraph 4~5, release 6~7, recovery 8~9, movement 10~11, death 12~15. 패턴 상태별로 구간을 재생한다. 매 공격마다 0~15를 한 번에 재생하면 안 된다. death는 마지막 프레임 유지. 이 시트는 정면 한 방향이며 4방향 시트가 아니다. 보스 원화를 90도 회전해 측면으로 사용하지 않는다. 투사체/경고 도형은 방향 회전 가능하다.

## 5. 공격별 정확한 계약

- 모든 공격은 먼저 선명한 바닥 경고를 보여준다. 장식 광선과 실제 피해 도형을 혼동하지 않는다. 경고의 끝점·너비·반경은 실제 판정 데이터로 그린다. 가장 큰 피해 범위가 화면 밖에서 예고 없이 시작되면 안 된다.
- 냉기 부채꼴: 발동 전 방향 고정, 각도 안에 있고 기둥에 차폐되지 않은 대상만 피격. 빙결 장판은 낙하지점 공격으로 기둥 뒤도 도달하지만 기둥 내부 셀은 제외한다. 둔화는 지속시간 갱신 방식, 무한 중첩/영구 빙결 금지.
- 산성 투척: 투사체가 먼저 닿은 벽/기둥에서 소멸한다. 포자 지대는 바닥 영역이며 위에서 떨어져 차폐되지 않는다. 동일 보스의 겹친 독 지대는 같은 피해 그룹의 tick 간격을 공유한다.
- 조준 사격: 조준선 → 타깃 고정 → 발사. 회전 레이저: 회전 방향 예고 → 안전 각도 확인 → 일정 각속도 회전. 매 프레임 최초 차폐물까지 레이 길이와 표시 길이를 동시에 자른다. 기둥을 관통해 뒤쪽에 피해를 주면 안 된다.
- 충격파: 확장하는 **고리**가 피해 도형이다. 단순히 내부 원 전체에 매 프레임 피해를 주지 않는다. 한 cast에서 대상당 1회. 기둥에 차폐되는 방사선 방향은 파동 표시도 약화/차단한다. 지연 폭발은 떨어질 지점에 표식을 남기고 고정 지연 후 폭발한다. 시전자 사망 시 남은 경고·판정을 취소한다.
- 중앙 융합체: HP 50% 이하에서 한 번만 분노 전환. 전환 동안 새 공격 판정을 만들지 않는다. 공격 조합을 순차 스케줄링하고 피할 길을 남긴다. 분노는 회복 시간/간격을 조절하며 기존 플레이어 스킬 범위를 바꾸지 않는다. 동시에 장판+돌진으로 출입구/모든 안전 공간을 막지 않는다.
- 연속 돌진: 매 돌진 사이에 다음 방향을 다시 예고하고 고정한다. 세 번을 보이지 않게 꺾어 따라가는 유도탄처럼 구현하지 않는다. swept collision으로 기둥/벽에 닿으면 멈추고 해당 회차 종료. 각 회차별 cast 식별자 사용. 얼음 파편은 기둥 차폐 적용.
- 뿌리: 지면 표시 후 뿌리가 솟는다. 구속은 1초를 초깃값으로 하고 재피격 면역을 2초 둔다. 이동 제한과 공격/스킬 입력 허용 여부를 명시한다. 사망/전투 종료 시 즉시 해제. 독 지대와 함께 영구 행동불능을 만들지 않는다.
- 이동 포격: 이동 중 포격하되 지정된 안전 속도로 이동한다. 포탄 착탄 위치는 발사 때 확정하고 1초 이상 예고. 포탄은 곡사 낙하이므로 기둥 뒤도 도달하지만 고정 기둥 면적은 유효 타깃에서 제외한다. 누출 흔적은 탱크 발밑 뒤에 일정 간격으로 배치, 수명·최대 개수·피해 tick을 제한한다.
- stage_catalog.json의 HP/피해/시간은 **새 단계의 조정용 초안**이다. 실제 1-1 수치는 덮어쓰지 않고 현행 값을 기준으로 난도를 조정한다. 크기 증가와 HP 증가를 같은 변수로 묶지 않는다.

## 6. 보스 입장 선택창: 실루엣이 반드시 보일 것

- 본부 컴퓨터에서 여는 실제 선택창에 9단계를 3×3 카드로 표시한다. 패널 기준 1120×720의 UI 좌표를 사용하고 화면 비율은 FitViewport 등 기존 UI 방식으로 대응한다. 런타임 글꼴 사용. 패널만 커지고 클릭 영역이 작은 문제가 없도록 입력 좌표를 UI 좌표로 unproject한다.
- **모든 카드에 해당 보스의 silhouette PNG를 넣는다. 잠겨 있어도 실루엣을 표시한다.** 9칸에 같은 그림/물음표를 복사하지 않는다. 선택한 보스의 컬러 이미지는 오른쪽 상세 영역에 크게 보여줄 수 있다. 실루엣과 컬러 파일 매핑은 stage_catalog.json을 따른다.
- 실루엣은 각기 다른 형태가 읽히도록 연한 테두리를 가진 어두운 색이다. 카드 배경과 섞여 안 보이는 검정 사각형이 되면 안 된다. 비율 유지 contain, 사방 여백 유지, 머리·다리·촉수 잘림 금지.
- 단계 ID·보스 이름·주요 패턴·해금 조건·입장 버튼은 코드로 그린다. 문자열을 이미지에 굽지 않는다. 잠금·선택·클리어는 중첩 가능한 별도 상태다. 선택 테두리 때문에 잠금 상태가 사라지면 안 된다.
- 클릭/방향키 이동으로 선택, Enter/입장 버튼으로 입장, Esc 닫기. 잠긴 단계는 입장 불가. 입장 연타/더블 클릭으로 전투 세션 2개를 만들지 않는다. 모달이 떠 있는 동안 플레이어·전투 입력을 막는다.

## 7. 투기장·해금·보상·저장

- 각 단계는 별도 배치 데이터로 기둥/엄폐물 위치를 달리하되 기존 바닥·벽·문을 재사용한다. 전체 맵 PNG를 늘려 바닥으로 사용하지 않는다. arena_layouts.json은 논리 배치 초안이며 기존 벽/문 연결 규칙으로 완성한다.
- 생성/로딩 후 플레이어 스폰→귀환문→전투 공간 연결과 플레이어 크기를 고려한 통로를 검사한다. 보스 초기 위치에 기둥/벽이 겹치지 않는지 확인한다. BFS는 점이 아니라 플레이어 반경만큼 장애물을 팽창시킨 탐색으로 보완한다.
- 전투 중 출입문 잠금, 토벌/실패 처리 중 중복 전환 방지. 보스 사망 시 남은 투사체·레이저·장판·지연 이벤트를 정리한다. 같은 프레임 동시 사망은 기존 정책을 유지하고 테스트로 명시한다.
- 보상은 기존 고가 아이템/LEGENDARY 목록과 확률 테이블을 재사용한다. 새 아이템 ID·가격을 발명하지 않는다. 1회 토벌 보상은 한 개, 본부 보관함으로 지급한다. 가방 8칸이 꽉 찼다는 이유로 보상을 잃지 않는다.
- runId+stageId 영수증으로 중복 지급 방지. 보상 아이템 인스턴스, 재화 변경이 있다면 해당 변경, 클리어, 다음 해금을 하나의 저장 트랜잭션으로 확정한다. 저장 실패 시 REWARD_PENDING, 확정 전 성공 복귀/중복 추첨 금지. 재도전의 새 run에는 현행 정책에 따라 새 보상 가능.
- 영구 강화/최대 HP/장착 스킬/쿨다운 계약은 기존 PlayerSession을 공유한다. 보스전 입장 시 HP를 임의로 100으로 리셋하지 않는다. 일반 연구소의 판매/가방 인계 처리를 보스 복귀에서 이중 실행하지 않는다.

## 8. 실행 순서와 검증

1. 실제 1-1 코드를 조사하고 현재 회귀 결과, 스킬 범위, 저장 포맷을 기록한다.
2. 공통 정의/패턴 상태/단계 해금 모델을 정리한다. 기존 구현으로도 같은 1-1이 실행되게 한다.
3. 9종 원화·실루엣·프레임·선택창 연결을 먼저 끝내고 실제 런타임 화면에서 잘림/크기를 확인한다.
4. 1-2/1-3 → 1-4/1-5 → 1-보스 → 2-1/2-2/2-3 순으로 패턴과 투기장 연결을 완성한다. 아트만 연결하고 implemented=true로 완료 보고하지 않는다.
5. 보상/해금/저장/복귀 통합, 회귀 확인, 문서 갱신까지 완료한다.

의미 있는 순수 Java 테스트: 9단계 ID와 다음 단계 연결, 기존 세이브 마이그레이션, 잠금 입장 차단, 패턴 발사 1회, 예고 중 무피해, 프레임 독립 시간 진행, 레이저 기둥 차폐, 돌진 swept 정지, 충격파 고리 1회 타격, 장판 겹침 tick 제한, 사망 후 예약 공격 취소, 뿌리 해제/면역, 보상 1회/저장 실패 재시도, 최대 HP 유지, 스킬 사거리 불변.

프로젝트의 실제 Gradle wrapper로 core:test 및 lwjgl3:build를 수행한다. 실제 실행 화면에서 3×3 실루엣, 9종 서로 다른 본체, 커진 보스와 유지된 스킬 범위, 기둥 뒤 차폐, 토벌/복귀를 확인한다. 합성 미리보기·로그·창 기동만으로 ‘실제 전투 화면 확인 완료’라고 쓰지 않는다. 실제 캡처가 불가능하면 그 한계를 명시하고 사용자가 재현할 경로를 제공한다.

완료 보고: 수정 파일, 보스별 실제 패턴/수치, 9단계 플레이 가능 여부, 스킬 범위 수정 전후, 보스 draw/collision/hurtbox 값, 테스트 결과, 실제 화면 증거, 남은 문제. 요청 없는 커밋/푸시는 기존 세션 권한에 따른다.
