# 난이도 선택창 깨짐 수정 프롬프트

현재 LibGDX(Java) 프로젝트에서 본부 대문과 상호작용했을 때 뜨는 난이도 선택창을 수정하라. 제공한 문제 화면 `image(10).png`에는 난이도 패널이 작거나 화면 아래로 밀려 있으며 오른쪽 아래에 큰 흰색/회색 사각형이 겹쳐 있다. 이를 단순한 에셋 교체로 해결됐다고 보고하지 말고 **실제 UI 렌더링 경로의 오류를 찾아 수정**하라. 현재 main의 HP HUD, 8칸 가방, 본부 지도, 대문, 페이드 전환 기능을 보존한다.

추가 에셋: `difficulty_modal_v2/runtime/difficulty_modal_960x640.png`, `difficulty_modal_v2/layout.json`. 원본 이미지는 `source/`에, 미리보기는 `preview.png`에 있다. 이전 `difficulty_panel_640x400.png`는 새 화면에서 사용하지 않는다. 신규 PNG의 투명 배경과 픽셀 아트를 유지한다.

## 1. 먼저 원인 확인

1. 본부의 대문 상호작용부터 난이도 선택 상태, 렌더러, Stage/Viewport, SpriteBatch, InputProcessor까지 실제 호출 경로를 확인하라. 첨부 화면과 동일한 창 크기(약 1280×960, 게임 영역은 타이틀바 제외)로 재현하고, 화면에 실제로 사용되는 텍스처와 UI 좌표를 기록하라.
2. 대문, 검은 반투명 배경, 패널, 선택 항목, 글자, 설명 표시를 한 요소씩 켜 보면서 어느 요소가 흰색 블록을 그리는지 찾아라. 작은 흰색 픽셀 텍스처를 확대해 칠하는 코드, 잘못된 TextureRegion UV, 투명 채널 누락, 잘못된 SpriteBatch 색/블렌딩/Scissor 상태, 월드 카메라와 UI 카메라 혼용, 폰트의 한글 글리프 미지원·과도한 스케일, 창 리사이즈 시 Viewport 미갱신을 조사하라. **증거 없이 원인을 단정하지 마라.**
3. 발견한 원인과 수정한 파일·줄기능을 보고하라. PNG를 바꿨다는 사실만으로 흰색 블록 문제를 해결했다고 판단하지 마라.

## 2. 화면 배치와 표시

- UI는 월드 카메라가 아닌 ScreenViewport 또는 기존 UI 전용 카메라에서 그린다. `resize()`에서 UI viewport를 갱신하고, 세계 렌더 후 `dim → panel → highlight → text` 순서로 한 번만 그린다. `begin/end`의 짝, `batch.setProjectionMatrix`, `batch.setColor(Color.WHITE)`, 표준 알파 블렌딩을 렌더 단계마다 확인하고 필요한 상태를 복원한다.
- 패널 원본 크기 960×640의 비율을 유지하여 화면 정중앙에 둔다. 표시 크기는 `scale = min(0.78 * viewportWidth / 960, 0.82 * viewportHeight / 640)`으로 계산한다. 이 식은 축소만 강제하지 않는다. 화면에 안전 여백이 생기는지 확인하고, 작은 창에서는 양쪽이 잘리지 않도록 한다. 패널 위치는 `(viewportWidth - 960*scale)/2`, `(viewportHeight - 640*scale)/2`이다.
- `layout.json`의 사각형은 이미지 **왼쪽 위 기준**이다. LibGDX Y축 변환을 한 번만 적용한다. 같은 변환으로 선택 강조와 클릭 영역을 계산해, 보이는 버튼과 클릭 영역이 일치하도록 한다.
- 본부 배경은 반투명 검정(약 0.55~0.65)으로 어둡게 한다. 화면 전체를 덮는 단일 투명 레이어만 그리며 불투명 흰 사각형을 사용하지 않는다. HP HUD는 본부에서도 화면 좌측 상단에 계속 보이게 한다.
- 패널 제목 `연구소 난이도 선택`, 세 선택 행 `쉬움`, `보통`, `어려움`, 하단 `Enter: 입장 · Esc: 취소`를 코드로 그린다. 각 행에는 몬스터 수 또는 위험도에 관한 짧은 설명을 붙인다. 1280px 너비 기준 제목은 30~36px, 행 이름은 28~32px 정도로 읽히게 하고, 실제 한글 글리프를 포함한 폰트를 로드해 네모/깨진 글자를 막는다.
- 마우스 호버, 선택, 키보드 방향키 탐색에 가시적인 강조를 적용한다. 클릭 및 Enter로 선택한 난이도를 확정하고 Esc로 본부에 남는다. 선택창이 열려 있으면 플레이어 이동/공격/다른 Space 상호작용을 막는다. 키를 계속 누르는 동안 여러 번 입장하지 않게 한다. 선택창 바깥 클릭은 기존 UX 규칙에 맞게 무시하거나 닫되 명시적으로 정한다.

## 3. 실제 게임 검증

- 난이도 선택창을 본부 대문에서 열어 **첨부 화면과 같은 창 크기**와 1280×720, 960×540에서 각각 스크린샷을 찍어라. 세 행·제목·하단 안내가 모두 패널 내부에 있고, 선택창이 중앙에 있으며, 흰색 블록·잘림·글자 깨짐이 없는지 눈으로 확인하라. 시작 화면의 HP 100 표시도 확인하라.
- 리사이즈 전후에도 클릭 영역이 보이는 행에 맞고, 쉬움/보통/어려움의 선택 결과가 올바른 맵 설정으로 전달되는지 확인하라. Esc 취소와 재오픈이 정상 동작해야 한다.
- UI 좌표 변환·선택 상태의 경계 테스트를 추가하되, 단위 테스트 성공만으로 화면 검증을 대체하지 마라. `core:test`, `lwjgl3:build`, 실제 `lwjgl3:run` 결과를 구분해 보고하고 전후 스크린샷 경로를 제시하라. 실패 또는 수동 확인 필요 항목은 그대로 표시하라.

우선 이 선택창 오류를 완전히 수정한 뒤 연구소 방 배치 작업을 계속하라. 수정 내용을 `ARCHITECTURE.md`, `TEST_PLAN.md`, `CHANGELOG.md`에 반영하라.
