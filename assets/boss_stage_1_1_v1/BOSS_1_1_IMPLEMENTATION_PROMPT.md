# 본부 메인 컴퓨터 → 보스 1-1 → 보상 → 본부 복귀 구현

기존 LibGDX / Java 8 게임에 별도 보스 모드의1-1을 완성하라. 실제 소스 조사 후 구현·테스트·실행 확인·문서 갱신까지 수행한다. 이번 단계에서 이후 보스들을 미리 만드는 대신1-1의 완전한 플레이 흐름을 만든다. 제공 에셋과 JSON은 구현 재료이며 현재 게임에 연결되었다는 뜻은 아니다.

## 1. 기존 구조와 범위

- 실제 프로젝트 규칙/패키지, HeadquartersScreen/메인 컴퓨터 상호작용, MapTransitionController, PlayerSessionState, 보관함·지갑·저장 프로필, 전투·피해·무적·사망, 돌진/스킬, 자산/뷰포트/입력 라우터, LootTableCatalog를 읽는다.
- 일반 연구소의 난이도 선택/랜덤 생성과 별도의 `BossStageId`/보스 모드 진입 경로를 둔다. 메인 컴퓨터에서 Space로 보스 단계 선택창을 연다. 기존 컴퓨터 아트·Space 안내·공용 패널/버튼/슬롯을 재사용한다.
- 기존 본부 남쪽 대문은 일반 연구소 입장 동작을 유지한다. 보스전 종료를 일반 탐사 귀환으로 잘못 처리해 가방 이관·루트 재생성·프로필 초기화가 중복 실행되지 않게 한다.
- 새 모드도 HP·스킬 해금/강화·장착·등록 키·쿨다운·재화·보관함을 같은 세션/프로필에서 사용한다. 보스 때문에 플레이어 최대 HP를100으로 초기화하지 않는다.

## 2. 단계 선택과 해금

- 저장된 진행이 없는 프로필은1-1만 해금/입장 가능하다. 이후 단계는 잠김으로 보인다. 저장 데이터가 있으면 실제 진행을 복원한다.
- 단계 목록은 `data/stages.example.json`처럼 `progressUnlocked`, `implemented`, `cleared`를 구분한다. 이번 빌드에서 구현되는 것은1-1뿐이다.
- 1-1 첫 토벌 성공은1-2의 진행 해금을 기록한다. 하지만1-2 전투가 아직 없으면 UI에 '해금됨 · 준비 중'으로 표시하고 입장 버튼은 비활성화한다. 준비되지 않은 맵으로 보내거나 예외를 내지 않는다.
- 재도전은 허용하며 새 runId를 발급한다. 각 유효 토벌 runId당 보상1개다. 최초 클리어의 다음 단계 해금과 반복 토벌 보상은 별도 기록이다.
- 입장 확정 시 profile/stage/runId/attemptSeed를 저장한다. UI 더블클릭으로 같은 시도 화면이2개 생기지 않게 전환 중 버튼을 잠근다. 선택창을 열기만 해서는 새 runId나 보상을 만들지 않는다.

## 3. 보스와 광장

- 보스 이름 초안은 **원심 배양체 C-01**이다. 기존 몬스터를 확대하지 않고 동봉의 생물 배양 탱크+원심분리 기계+넓은 지지 다리 실루엣을 사용한다.
- 초안 HP600. 수치와 모든 패턴/시간은 JSON 한 곳에서 읽는다. 기존 기획에서 확정된 보스 밸런스가 있으면 우선하고 차이를 보고한다. 기본 공격 접촉만으로 피해를 주는4번째 패턴은 추가하지 않는다.
- 동봉 `arena.example.json`은32×24 타일 광장, 외곽 벽, 남쪽 입장/귀환 겸용 문, 기둥4개와 시작/보스 위치 초안이다. 바닥은 반복 타일로 조립하고 기존 벽/코너를 사용한다. 통짜 그림을 배경 충돌로 쓰지 않는다.
- 실제 기둥 바닥 footprint와 보스/플레이어 actor 크기를 반영해 기둥 사이 통과 폭과 문 앞 공간을 검증한다. 그림 전체 사각형이나 투명 여백까지 solid로 잡지 않는다.
- 보스 스프라이트의 표현 크기, 이동 collider, hurtbox는 각각 메타데이터로 관리한다. 표현 크기는 플레이어보다 확실히 크게 하되 공격 범위·기둥 충돌을 그림 크기만 보고 추정하지 않는다.
- 보스 몸체는 카메라를 향한 고정 직교 뷰다. 원형 발사구/에너지 표시만 조준 방향을 표현하고 몸체를 임의90도 회전하지 않는다. 돌진은 월드 방향 벡터로 이동하며 이 팩의 돌진 자세와 꼬리 효과를 사용한다.4방향 전용 몸체가 들어있다고 가정하지 않는다.

## 4. 보스 전투 상태와 시간

- 상태: ENTERING → INTRO → COMBAT → DYING → REWARD_PENDING → CLEARED → RETURNING. 플레이어 사망은 FAILED 흐름으로 분기한다. 상태 전이를 한 곳에서 관리하고 Screen별 boolean 조합으로 중복 토벌/복귀를 처리하지 않는다.
- 입장 완료 후1초 소개/대기 초안 뒤 전투를 시작한다. 대문은 잠금 상태로 전환하고 보스 HP바를 표시한다. 소개 시간 동안 보스 공격·플레이어 피해를 막되 이동 허용 등 정책은 데이터로 명시한다.
- 보스 AI는 한 번에 하나의 주 패턴만 실행한다. 각 패턴은 TELEGRAPH → ACTIVE → RECOVERY로 구분한다. 초기1회씩 투척→장판→돌진을 보여준 뒤 시드 기반 가중 선택하며 같은 패턴이 즉시 반복되지 않게 한다.
- 패턴의 elapsed 시간, 이벤트 시각, 활성/종료, 시각 프레임은 같은 시뮬레이션 시계를 사용한다. 렌더러에서 frame==N일 때 피해를 주지 않는다. 이전 시간<eventTime≤새 시간 경계로 한 번만 실행하고0초 이벤트는 시작 시 한 번 처리한다.
- 한 프레임에 여러 사건을 건너도 시간순으로 모두 처리한다. patternInstanceId/eventId/projectileId와 대상 entityId로 중복 명중을 막는다. 일시정지 중 보스·투사체·장판·회복 동작·VFX·쿨다운 시간이 함께 멈춘다.
- 사망/종료 시 예약된 패턴 이벤트를 취소하고 투사체·장판·돌진 판정을 제거한다. 보스가 죽었는데 늦은 타이머가 플레이어를 죽이거나 결과창 뒤에서 공격하지 않게 한다.

## 5. 패턴1 — 시약 투척

- 초안: 예고0.8초, 조준 고정0.5초, 발사0.8/0.95/1.10초, 회복1.20~2.10초. 주 방향과±18도에3개의 따로 식별되는 투사체를 순차 발사한다. 각 피해20, 속도6.5타일/초, 최대 거리18타일, 반경0.18타일.
- 예고 중 보스의 준비 자세와 발사 방향 선을 표시한다.0.5초에 목표 방향을 고정한 뒤 추적하지 않는다. 조준이0벡터면 마지막 유효 방향을 사용한다. 발사 전에 플레이어에게 피해가 들어가면 안 된다.
- 실제 발사 이벤트 때 투사체를 만든다. 이동 전후 구간의 swept 충돌로 기둥·닫힌 문·벽·플레이어 중 가장 먼저 닿은 대상을 처리한다. 얇은 기둥을 delta 때문에 통과하지 않는다.
- 기둥/벽/닫힌 문 충돌은 착탄 효과만 표시하고 뒤의 플레이어는 맞지 않는다. 플레이어 명중은 기존 보호막→HP 피해 파이프라인을 한 번 사용한다. 투사체는 첫 충돌/수명 종료에 제거한다.
- 이 패턴은 바닥 장판을 남기지 않는다. 착탄 효과와 장판 패턴을 혼동하지 않는다. 여러 투사체의 연속 명중은 기존 플레이어 무적시간 규칙을 따른다.

## 6. 패턴2 — 오염 장판

- 초안: 시전 시작 때 플레이어의 현재 바닥 위치를 고정하고 반경2.2타일 원형 예고를1초 표시한다. t=1.0초에 장판 활성, 활성 후4초 유지, 피해8을0.5초 간격으로 적용한다. 보스 회복 동작은1.2~2.2초다.
- 예고와 장판의 원점/범위를 같은 데이터로 그린다. 예고 중에는 피해가 없다. 장판 아트의0~1번 작은 생성 프레임은 예고의 마지막2/15초에만 보여주고,1초 활성 시점에는 완성 크기의2~5번 반복 구간으로 넘어간다. 작은 웅덩이만 보이는데 최대 범위 피해가 먼저 들어가지 않게 한다. 활성 순간 첫 틱을 허용하며 이후 전역 틱 일정으로 처리한다. 장판 경계를 매 프레임 밟는다고 틱이 리셋되어 연타되지 않는다.
- 캐릭터의 실제 발/hurtbox가 활성 영역과 겹치면 피해 파이프라인으로 처리한다. 여러 프레임 겹침과 재진입에 따른 중복 피해를 막고 actor별 다음 허용 틱을 관리한다.
- **이 장판은 낙하 오염 방식이라 기둥 뒤에도 떨어진다.** 기둥이 투척을 막는다고 장판까지 차폐하지 않는다. 기둥 footprint 자체는 피해 영역에서 제외하되 원 안의 접근 가능한 바닥은 가림 여부와 무관하게 위험하다. 벽 바깥/통행 불가 셀에는 효과/피해를 놓지 않는다.
- 목표가 벽/기둥 안이면 가장 가까운 유효 바닥으로 결정론적으로 보정한다. 경고 범위를 순간적으로 플레이어를 쫓게 이동하지 않는다. 작은 원 경고 뒤 더 큰 피해 원을 갑자기 만들지 않는다.
- 최대 활성 장판2개로 제한하고 다음 패턴까지 최소0.6초 여유를 둔다. 장판이 남아 있어도 주 패턴 상태는 회복 종료 후 이동할 수 있다. 허용 개수와 겹침 피해 정책은 데이터로 명시하고 무한 장판 누적을 막는다.
- 겹친 장판은 플레이어에게 최대 하나의 장판 틱 피해만 적용하는 초안을 사용한다. areaInstanceId별 이벤트는 유지하되 플레이어의 공통 장판 피해 간격으로 겹침 폭딜을 제한한다.
- 만료/보스 사망/맵 종료 즉시 판정을 해제하고 짧게 페이드한다. 잔상이 보여도 피해는 없다는 상태를 명확히 구분한다.

## 7. 패턴3 — 장비 돌진

- 초안: 예고0.9초, 조준 고정0.55초, 속도9타일/초, 최대 돌진8타일, 피해30, 회복0.9초. 고정 방향의 직선 경로 예고를 표시한다.
- 돌진 collider를 원/캡슐/박스 중 기존 지원 형태로 정의하고, 예고의 폭을 그 collider+실제 타격 여유와 맞춘다. 이미지 꼬리를 피해 범위로 취급하지 않는다.
- 벽·닫힌 문·기둥과의 첫 swept 충돌 시 접촉 표면 앞에서 즉시 정지한다. 기둥은 파괴되지 않으며 보스가 통과하거나 반대편에 순간이동하지 않는다. 막히면 충돌 효과 후 회복 동작으로 전환한다.
- 플레이어와 실제 돌진 구간이 교차하면1돌진당1회 피해를 준다. 정지 후/회복 중 몸체가 겹친다고 계속 돌진 피해를 주지 않는다. 보호막과 무적시간 처리는 공통 파이프라인을 사용한다.
- 회복 중에는 다음 공격을 시작하지 않는다. 기둥에 막힌 보스를 플레이어가 공격할 수 있는 시간이 시각적으로 보여야 한다.

## 8. 기둥 차단 규칙 — 패턴별로 분리

| 대상 | 기둥 처리 |
|---|---|
| 보스 투척 투사체 | 첫 충돌에서 차단/소멸 |
| 보스 돌진 | 첫 충돌에서 이동·타격 종료, 회복 진입 |
| 보스 오염 장판 | 기둥 뒤 차폐 없음, 기둥 자체 footprint 제외 |
| 플레이어 이동/돌진 | 기존 solid 충돌 규칙으로 막음 |
| 플레이어 전기 투척 | 기존 첫 solid 충돌 규칙으로 막음 |
| 플레이어 충격파 | 앞 단계의 solid 차폐 규칙을 유지 |

차단은 공용 solid 데이터를 기반으로 하되 패턴별 정책을 분리한다. 렌더러의 기둥 그림을 지웠다고 물리 장애물까지 사라지는 구조를 만들지 않는다.

## 9. HP바·피격·사망·실패

- 보스 HP바는 화면 상단 중앙 UI 뷰포트에 고정한다. 플레이어 좌상단 HP HUD와 겹치지 않게 하고 이름/현재HP/최대HP/채움은 런타임으로 그린다. 보스 본체 위 숫자만 달고 HUD 요구를 누락하지 않는다.
- 보스 피격·HP 감소·사망은 공통 전투 모델을 사용한다. 사망 임계에서 한 번만 DYING으로 전이한다. 충격파/감전/넉백에 대한 보스 저항은 JSON으로 정의한다. 초안은 넉백 면역·강제 경직 면역이며 전기 직접 피해는 받는다. 감전 표시만 나오고 행동 중단은 면역임을 효과 설명/피드백에서 구분한다.
- DYING에서는 공격·이동을 멈추고 사망6프레임을1회 재생한 뒤 마지막 프레임을 유지한다. 시트의 전투 자세/사망 프레임을 idle로 되돌리지 않는다.
- 플레이어가 죽으면 기존 쓰러짐/입력 차단을 유지하고 보상·단계 해금을 발생시키지 않는다. 실패 결과에서 재도전(새 runId)/본부 복귀를 제공한다.
- 기존 사망·복귀 규칙이 있으면 재사용한다. 아직 없다면 보스 모드 실패 복귀 시 현재 최대HP로 회복하고 보관 물품/영구 진행을 보존하는 최소 흐름을 명시적으로 구현한다. 일반 연구소의 사망 물품 규칙을 임의로 바꾸지 않는다.
- 같은 시뮬레이션 시각에 플레이어와 보스가 함께 죽으면 이 단계 초안에서는 실패를 우선한다. 사건 순서를 일관되게 처리하고 보상/실패가 동시에 저장되지 않게 테스트한다.

## 10. 보상·해금·중복 방지

- 유효 토벌은 사망 판정과 승리 상태가 확정된 사건이다. 아이템은 기존 카탈로그의 활성 LEGENDARY 고가 풀에서1개를 선택한다. 실제 아이템 ID·가격·가중치는 기존 `loot_tables.json`/LootTableCatalog를 유일한 기준으로 사용한다. 새 파일에 이름/가격을 복사하지 않는다.
- 보상은8칸 탐사 가방과 별도의 **본부 보관함**으로 지급한다. 가방이 찼다는 이유로 보상 삭제/자동 판매/바닥 방치하지 않는다. 결과 화면에는 지급 아이템·등급·가치와 '본부 보관함 지급'을 표시한다.
- runId+stageId에 보상 수령 영수증을 기록한다. `토벌 기록 + 다음 단계 진행 해금 + 보상 아이템 인스턴스 추가 + run 보상 완료`를 하나의 다음 프로필로 만들어 원자적으로 저장한다.
- 저장 성공 후 CLEARED UI와 귀환문을 활성화한다. 실패하면 REWARD_PENDING과 동일 선택 보상을 유지하고 다시 저장할 수 있게 한다. 저장 실패 중 성공 처리/물품 제거/다음 단계 재화 사용/자동 본부 복귀로 앞서가지 않는다.
- 보상 선택은 저장된 runId에서 파생한 시드/선택 기록으로 안정화한다. 결과창 재진입/저장 재시도/화면 재생성/앱 재실행으로 다른 아이템을 다시 뽑거나 보상을2개 추가하지 않는다.
- 동일 토벌 콜백, 복귀 버튼 더블클릭, 사망 애니메이션 종료 재호출, 저장 완료 콜백 중복을 모두 방어한다. 보상 receipt와 itemInstanceId가 중복되지 않게 모델에서도 검증한다.
- 재도전으로 새 runId를 시작해 다시 유효 토벌한 경우에는 새 보상1개를 허용한다. 최초 클리어 해금 기록은 중복 누적하지 않는다.
- 재실행 시 이미 저장된 receipt를 먼저 확인한다. 로컬 저장 실패를 무시하고 UI만 성공으로 바꾸지 않는다. 앱 저장 경로/임시쓰기/원자교체/백업/마이그레이션은 앞 단계 저장기를 재사용한다.

## 11. 본부 복귀와 자원 수명

- 승리 후 귀환문 근처 Space 또는 결과창 본부 복귀 버튼으로 기존0.35초 페이드를 재사용한다. 복귀는 한 번만 실행한다. 자동으로 미구현1-2에 진입하지 않는다.
- MapMode가 BOSS인 복귀에서 일반 연구소 가방 인계/탐사 루트 초기화를 중복 호출하지 않는다. 영구 보관함/강화/장착/쿨다운·돈은 유지한다. 보스전 임시 엔티티/위험영역/음향 핸들은 정리한다.
- Texture/애니메이션 시트는 GameAssets의 기존 소유 규칙을 따른다. Screen 교체 시 공유 Texture를 임의dispose하지 않는다. UI와 월드의 카메라/입력 좌표를 분리하고 결과창이 떠 있으면 월드 스킬 입력을 차단한다.

## 12. 에셋 적용

- 이 폴더를 프로젝트의 적절한 자산 위치에 복사하고 `asset_catalog.json`, `animations.json`, `data/`를 사용한다. 실제 경로는 AssetPaths 한 곳에서 관리한다.
- 본체 idle/attack/death는 같은 보스 디자인을 바탕으로 만든 시트다. 몸체 셀은192×192, VFX 셀은128×128이다. 프레임마다 trim/크기 변경을 하지 말고 JSON 앵커와 공통 배율을 사용한다.
- attack 시트의 프레임 인덱스는 상태별 자세다. 시트 전체를 무작정 처음부터 끝까지 모든 공격에 재생하지 않는다. 예고/발사/회복/돌진 구간을 JSON에서 선택하고 게임 타임라인에 맞춰 재생한다.
- 공격 예고 원/직선과 HP 채움은 정확한 범위 표시를 위해 코드로 만든 별도 PNG/런타임 기하를 제공한다. 아트의 번쩍임이 아니라 데이터의 원점·반경·폭·활성 시점이 판정 기준이다.
- 광장 바닥은 반복 타일이다. 기둥은 발 footprint, 문은 통로 socket으로 배치한다. 입장/귀환은 같은 남쪽 문을 공유하며 닫힘/열림/잠금 상태를 사용한다. 별도의 측면/후면 대문이 있다고 가정하지 않는다.
- 기존 아이템·등급 테두리·주인공·회복·스킬·메인 컴퓨터·벽/코너는 재사용한다. 새 효과음은 이 팩에 포함하지 않았다. 기존 사운드가 있다면 SFX 끄기 설정을 따르며 재사용하고 없는 파일을 로드하지 않는다.
- PNG는 RGBA/Nearest, 바닥은 불투명 반복 타일, 이름/비용/HP/단계 번호/보상명은 코드로 표시한다. preview 이미지를 런타임 배경으로 사용하지 않는다.
