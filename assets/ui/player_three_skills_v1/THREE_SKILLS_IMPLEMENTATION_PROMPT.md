# 추가 스킬 3종 구현 프롬프트

기존 폐쇄 연구소 게임의 공통 스킬·해금·장착·단축키·쿨다운·강화·저장 구조에 충격파, 전기 투척, 보호막을 완성하라. 실제 코드 조사부터 구현, 판정/애니메이션 검증, 문서 갱신까지 수행한다. 에셋만 등록하거나 효과만 보이는 상태를 완료라고 보고하지 마라.

## 1. 기존 구조와 범위

- 실제 프로젝트 규칙과 패키지를 확인하고, 앞 단계의 돌진/회복 공통 실행 경로, Skill 관련 모델, CombatSystem, 피해/무적/사망/넉백, 투사체, 몬스터 AI, 충돌 그리드, 강화 카탈로그, 프로필 저장과 UI를 읽는다.
- 공통 구조가 이미 있으면 확장한다. 없으면 기존 돌진과 회복도 유지하는 최소 공통 모델부터 연결한다. Screen에 스킬별 키 분기를 추가하는 방식으로 우회하지 않는다.
- 이 단계는 세 스킬의 아이콘 → 발동 → 실제 판정 → 쿨다운 → 해금/강화 노드 → 장착/저장까지다. 보스·새 맵·새 몬스터·새 상점은 범위 밖이다.
- 새 입력 키를 스킬 코드에 하드코딩하지 않는다. 기본 추가 슬롯 1/2/3을 안내하되 실제 등록 키를 사용한다. F 돌진, Q 회복, R 가방, H 귀환 안내, Space 상호작용과 충돌하지 않는다.
- 모든 스킬은 본부 강화대에서 해금한 뒤 스킬 목록에서 빈 활성 슬롯에 장착한다. 잠긴 슬롯을 자동 해제하거나 기본 스킬을 임의로 빼지 않는다. 슬롯 부족은 기존 슬롯 확장 노드로 해결한다.

## 2. 데이터와 시간의 단일 기준

- 동봉 `data/skills.example.json`, `data/upgrade_nodes.example.json`은 **이번 단계에서 제안하는 초기 밸런스 초안**이다. 기존 확정 데이터가 있으면 우선하고 차이를 보고한다. 기존 카탈로그에 새 항목을 병합하며 파일 전체를 덮어써 이전 노드를 지우지 않는다.
- 거리 단위는 예제의 `worldUnit = oneTile`이다. 실제 프로젝트 좌표가 픽셀이면 한 곳에서 변환한다. UI 픽셀, VFX 셀 픽셀, 월드 타일 단위를 섞지 않는다.
- 공통 스킬 정의는 skillId, cooldownSeconds, cast/startup 시간, 판정 이벤트, 범위/속도/수명/피해/상태효과, iconId, animationId를 가진다.
- **판정 타임라인은 게임의 고정/누적 시뮬레이션 시간 기준 데이터**다. 렌더러가 현재 프레임을 보며 피해를 주지 않는다. 시각 프레임도 동일한 elapsed 시간으로 선택한다. 한 정의에서 파생해 판정과 표시가 다른 상수를 쓰지 않게 한다.
- 이벤트 경계를 이전 시간 < eventTime ≤ 새 시간으로 처리하되 t=0 이벤트는 시작 시 한 번 실행한다. 프레임 드롭으로 여러 경계를 건너면 모두 순서대로 처리한다. 부동소수점 동일 비교나 매 프레임 if(frame==N)으로 중복 판정하지 않는다.
- castId, eventId, 대상 entityId로 해당 시전/이벤트의 명중을 중복 방지한다. 재시전은 새 castId다. 죽은 대상과 제거된 엔티티는 다시 타격하지 않는다.
- 공통 규칙: 생존·해금·장착·쿨다운·입력 허용 검증 후 시전 시작 성공 시 쿨다운을 한 번 시작한다. 준비 시간 중 사망/맵 전환으로 중단되면 아직 발생하지 않은 효과를 취소하되 사용한 쿨다운은 되돌리지 않는다. 잠김·쿨다운·UI 차단 같은 시작 실패는 소모하지 않는다.
- 일시정지는 시전 시간·쿨다운·투사체·감전·보호막 시간·VFX를 함께 멈춘다. 메뉴 정책도 기존 게임 시간 정책을 따른다. 장착 해제나 키 변경으로 쿨다운을 리셋하지 않는다.

## 3. 충격파: 주변 피해와 밀어내기

- 기본 초안: 피해30, 최대 반경2.5타일, 밀어내기0.8타일, 쿨다운6초. 캐릭터 발 위치에서 원형으로 퍼진다.
- 원점은 시전 시작 위치에 고정한다. 발동 후 캐릭터가 이동해도 이미 나온 충격파가 몸을 따라 이동하지 않는다.
- 동봉 8프레임/15fps 충격파 기준: 0번 프레임은 중심 예고, 1번(1/15초)부터 피해 활성, 4번(4/15초)에 최대 반경, 5번(5/15초)에 피해 종료, 남은 프레임은 잔상이다. 0번의 작은 중심광에는 피해가 없다.
- radiusCurve를 데이터로 사용해 그림의 고리와 같은 속도로 판정 반경이 증가한다. 시작부터 최대 반경 원 전체에 피해를 주면 안 된다. 최대 반경에서도 잔상이 사라질 때까지 무한 재타격하지 않는다.
- 직전/현재의 파면 사이를 검사하고, 몬스터의 실제 hurtbox와 교차한 최초 시점에 피해·밀어내기·피격 VFX를 한 번 적용한다. 원점 바로 위의 대상도 첫 활성 구간에서 누락되지 않게 한다.
- 몬스터 이동과 큰 delta로 파면을 건너는 경우도 검출한다. 고정 서브스텝 또는 연속 교차 검사로 처리하고 한 스텝에 여러 몬스터를 타격할 수 있다.
- 벽·닫힌 문·실제 solid 가구 뒤로 피해가 새지 않게 원점→목표 충돌 표면의 가시성/차폐를 검사한다. 장식 오버레이는 차폐로 취급하지 않는다. 꺾인 복도 벽 너머로 원형 거리만 보고 때리지 않는다.
- 밀어내기는 원점에서 바깥 방향이다. 중심과 같은 위치면 안정적인 보조 방향을 사용해 NaN을 막는다. 벽·문·가구를 관통하지 않도록 기존 이동/충돌 해결기를 통과시킨다. 넉백 면역·보스 저항 태그가 있으면 존중한다.
- 렌더 반경과 논리 반경을 F1 등 디버그로 함께 확인한다. 셀 전체 크기가 반경이라고 가정하지 말고 `animations.json`의 visualExtent와 실제 PNG의 고리 외곽에 맞춰 draw scale을 조정한다.

## 4. 전기 투척: 지정 방향 투사체

- 기본 초안: 직접 피해25, 속도10타일/초, 최대 이동 거리8타일, 충돌 반경0.18타일, 감전0.5초, 쿨다운5초. 관통·연쇄·광역 피해는 이번 기본 버전에 없다.
- 시전 시작 시 월드 방향을 확정한다. 기존 조준 시스템이 있으면 재사용한다. 마우스 조준을 쓰면 UI→월드 좌표를 올바르게 변환하며, 마우스가 UI 위면 발동시키지 않는다. 조준 벡터가 0이면 마지막 유효 이동/바라보기 방향을 사용한다. 중간에 마우스를 움직여 투사체가 자동 유도되지 않게 한다.
- 준비 시간2/15초 뒤에 spawn_projectile 이벤트를 한 번 발생시킨다. 준비 표시는 착탄 첫 프레임을 작게 재사용할 수 있지만 이때 피해를 주지 않는다. 투사체는 이벤트 시점의 플레이어 발/발사구에서 나타나고 방향은 시작 시 확정한 방향이다.
- 아트의 기준 방향은 오른쪽(+X)이다. 이동 방향 벡터와 같은 각도로 회전해 표시한다. 월드 캐릭터 가구 방향 제한과 달리 이 에너지 투사체는 방향 회전이 가능하다.
- delta가 커도 벽을 통과하지 않도록 이전 위치→새 위치 구간에 swept circle/충돌 검사를 수행한다. 벽·닫힌 문·solid 가구와 몬스터를 모두 비교해 **가장 먼저 닿은 충돌**만 처리한다. 단순 도착점 겹침 검사만 쓰지 않는다.
- 몬스터 첫 충돌이면 직접 피해25와 감전을 한 번 적용하고 투사체를 제거한다. 표면 충돌 위치에 착탄 VFX를 즉시 시작한다. 벽 충돌은 VFX만 나오며 벽 뒤 몬스터는 맞지 않는다. 최대 거리 도달 시 피해 없이 소멸한다.
- 감전은 상태 모델에서 남은 시간을 관리해 이동/공격 시작을 잠깐 막는다. 무조건 AI를 영구 정지시키거나 애니메이션만 번쩍이게 하지 않는다. 면역/저항 태그가 있으면 적용하고 기본 새 보스 태그를 임의로 만들지 않는다.
- 기존 공격의 windup/active/recovery 중 감전 중단 규칙을 명시한다. 기본은 새 행동 시작을 막고 아직 활성화되지 않은 공격을 취소하는 것이다. 이미 확정된 피해를 과거로 되돌리지 않는다.
- 감전 재적용은 max(현재 남은 시간, 새 지속 시간)으로 갱신하고 무한 중첩 시간을 더하지 않는다. 감전 VFX는 실제 감전 종료와 함께 정리한다. 착탄 VFX의 짧은 표시 시간과 상태 지속 시간을 혼동하지 않는다.

## 5. 보호막: 일시적인 피해 흡수

- 기본 초안: 흡수량60, 활성 지속4초, 쿨다운12초. 준비2/15초 뒤 activate_shield 이벤트에서 실제 방어가 시작된다. 준비 중에는 아직 피해를 막지 않는다.
- 보호막은 플레이어를 따라다니며 별도 collision 장애물로 만들지 않는다. 시전 시작부터 0~1번 프레임으로 생성 과정을 보여주고, 2번 프레임 시각에 방어가 시작되면 2~5번 프레임을 반복한다. 실제 방어 시작과 완성 버블이 나타나는 시점을 맞춘다.
- 피해 처리는 기존 공통 피해 파이프라인 하나에서 한다: 유효 피해/무적 검증 → 기존 방어 보정 → 보호막 흡수 → 남은 피해만 HP 차감 → 피격/사망 결과. 보호막 렌더러가 HP를 복원하는 방식으로 구현하지 않는다.
- 예: 보호막20/입력 피해35이면 보호막0, HP 피해15. 보호막이 모든 피해를 흡수하면 HP는 그대로다. 무적 등으로 거절된 공격은 보호막도 깎지 않는다.
- 수용된 피격의 무적시간은 기존 규칙을 따른다. 흡수에 성공했다는 이유로 겹쳐 있는 적이 프레임마다 보호막을 깎지 않도록 타격 재사용/무적 처리를 일관되게 한다. 이미 분리된 다중 타격 판정은 기존 규칙을 유지한다.
- 흡수량이0이면 그 시점에 방어를 종료하고 파괴 VFX를 한 번 시작한다. 이후 파괴 애니메이션이 보여도 피해는 더 막지 않는다. 잔여 피해는 같은 사건에서 처리하며 다시 한 번 별도 피해 이벤트로 넣지 않는다.
- 지속 시간이 먼저 끝나면 방어 종료 후 마지막 버블의 알파를 짧게 줄여 자연스럽게 사라지게 한다. 시간 만료와 파괴를 구분한다. 파괴하지도 않았는데 깨지는 효과를 재생하지 않는다.
- 활성 상태의 중복 시전은 실패로 처리하고 쿨다운/흡수량을 다시 설정하지 않는다. 수치가 낮아져 쿨다운이 먼저 끝나도 중복 버블을 쌓지 않는다.
- 사망/맵 이탈 시 보호막과 VFX를 정리한다. 슬롯 해제는 이미 발동한 보호막을 복제/재충전하지 않는다. 기본 정책은 활성 효과가 원래 만료될 때까지 유지되고 재시전은 장착 조건을 다시 따른다.
- 활성 시간이4초를 통과하는 큰 delta에서 피해 사건과 만료 사건을 시간순으로 해결한다. 만료 이후 피해를 보호막이 받아서는 안 된다. 동시각 만료는 만료를 먼저 처리한다.

## 6. 강화 트리·저장·장착

- 기존 체력/공격/스킬 트리에 새 skillId의 해금 노드와 강화 노드를 병합한다. 예제에는 해금+전용 성능 강화 총6개 노드가 있다. UI 좌표는 기존 트리 영역/스크롤에 맞춰 추가하고 이전 노드와 겹치지 않게 한다.
- 기존 슬롯 확장이 최대5개를 지원하는지도 확인한다. 기본2개+기존 추가1개만 지원한다면 4번째/5번째 활성 슬롯 확장 노드를 선행 조건을 두고 추가한다. 동봉 optionalSlotNodes는 그 경우만 쓰는 비용 초안이다. 기존 대응 노드가 있으면 중복 추가하지 않는다. 스킬 해금 자체가 슬롯 확장 효과를 갖게 하지는 않는다.
- 충격파 강화: 피해+10. 전기 투척 강화: 피해+10. 보호막 강화: 흡수량+30. 모두 대응 스킬 해금이 선행 조건이다. 초안 비용은 JSON 한 곳에서 읽는다.
- 스킬 해금, 성능 강화, 슬롯 확장을 별도 효과 타입으로 유지한다. 해금 구매만으로 스킬 슬롯을 늘리거나 이미 장착된 회복/돌진을 교체하지 않는다.
- 기본 공격력 강화가 스킬 피해에도 적용되는지는 기존 공식에 따른다. 이번 초안은 스킬 고정 기본 피해+전용 강화 방식이다. 일반 공격 보너스를 중복 가산하지 않는다.
- 지갑 차감+구매 기록+해금은 앞 단계 원자적 저장 흐름을 따른다. 실패 시 이전 상태를 유지하고, 저장/로드 후 강화 효과를 중복 적용하지 않는다.
- 장착 UI에는 세 아이콘·효과 설명·실제 계산된 값·쿨다운·잠긴 이유를 표시한다. HUD는 실제 등록 키와 skillId별 쿨다운을 보여준다. 숫자/등급/피해/쿨다운을 이미지에 넣지 않는다.
- 맵 전환과 재장착은 기존 쿨다운을 유지한다. 진행 중 투사체/충격파/버블은 맵 이탈 때 제거하고 새 맵에 이전 몬스터 참조가 남지 않게 한다. 저장은 구매·장착·쿨다운 스냅샷을 기존 정책대로 보존하고 진행 중 투사체를 세이브 파일에 저장할 필요는 없다.

## 7. 에셋·렌더링 적용

- 이 폴더를 `assets/ui/player_three_skills_v1/`에 복사한다. `asset_catalog.json`, `animations.json`의 실제 크기/셀/순서/앵커/반복 구간을 따른다.
- 아이콘3개는64×64다. 6종 VFX 시트는 셀128×128이며 전체 시트 크기와 개수는 JSON에 있다. 개별 프레임도 제공하지만 시트와 동시에 중복 로딩할 필요는 없다.
- 모든 VFX는 RGBA다. 검정 배경을 붙이지 않는다. 프레임마다 trim/자동 중앙 맞춤/크기 조절을 하지 말고 고정 셀과 같은 앵커를 사용한다.
- 충격파/충격 피격은 금빛, 전기 투사체/착탄은 청록, 보호막/파괴는 파랑이다. 실제 판정에서 피격 성공 시에만 피격 효과를 생성한다. 빗나갔는데 몬스터에 피격 효과를 미리 띄우지 않는다.
- 전기 투사체는 비행 중4프레임 반복, 보호막은 생성 후 반복 구간을 유지한다. 충격파·피격·착탄·파괴는1회 재생하고 제거한다. JSON의 타임라인은 초안 밸런스와 일치하도록 관리한다.
- 월드 좌표에서 그리는 효과와 UI 아이콘을 분리한다. 충격파는 바닥/엔티티 아래, 피격·착탄·보호막은 적절한 엔티티 위 레이어에 그린다. 보호막은 낮은 알파로 캐릭터가 읽히게 한다. HP HUD/미니맵 위에 월드 VFX를 덮지 않는다.
- GameAssets의 단일 소유/해제·Nearest 필터를 유지한다. 풀링이 이미 있다면 VFX/투사체 풀을 재사용하고 종료 시 castId/대상 기록/상태를 초기화한다. 엔티티 ID 재사용으로 이전 시전 명중 기록이 새 몬스터에 적용되지 않게 한다.
- 효과음이 기존에 있으면 일치하는 것을 재사용하고 SFX 끄기 설정을 따른다. 이 팩에는 새 효과음 파일은 포함하지 않았다. 존재하지 않는 사운드를 로드하지 않는다.

## 8. 필수 검증과 완료 기준

- 단위 테스트: 시전 시작 실패 무소모, 공통 쿨다운1회 시작, 각 데이터 이벤트1회 처리, 큰 delta에서 경계 누락/중복 없음, frame elapsed와 판정 phase 일치.
- 충격파: 바깥 대상이 처음부터 맞지 않음, 파면 도달 시1회 명중, 여러 적 동시 명중, 이동하는 적/원점 적, 벽 차폐, 벽에 넉백해도 관통/NaN 없음.
- 전기: 방향 고정, swept 충돌로 얇은 벽 통과 방지, 같은 구간 벽이 몬스터보다 앞이면 피해 없음, 1투사체1충돌, 감전 적용·연장·정상 복귀, 사거리 소멸, 죽은 대상 무시.
- 보호막:60상태에서35피해→25남고HP그대로,20상태에서35피해→0과HP15감소, 무적 거절 피해 미차감, 만료 이후 방어 없음, 파괴1회, 만료와 파괴 구분, 중복 시전 차단, 이미 죽은 캐릭터에게 방어/회복 오용 없음.
- 통합: 해금→장착→등록키 발동→HUD 쿨다운→강화 구매 후 실제 수치 변화→저장/재시작 복원. F/Q/R/H/Space 기존 입력 유지, UI 열린 상태 스킬 차단.
- 30/60/144fps와 큰 delta에서 총 피해·명중 횟수·이동/시간 결과가 동일한지 비교한다. 일시정지/맵 전환/사망 중단도 확인한다.
- `core:test`, `lwjgl3:build`와 실제 게임 조작을 확인한다. 디버그로 타일 격자, 범위/파면, 투사체 sweep, 보호막 잔량/시간, cast elapsed/event 로그를 선택적으로 표시해 VFX와 대조한다. 기본 화면에는 디버그를 숨긴다.
- 실제 실행 캡처가 불가능하면 그 사실을 적는다. 제공된 GIF는 에셋 예시이고 실제 게임 판정 검증이 아니다.
- ARCHITECTURE.md, GAME_RULES.md, TEST_PLAN.md, CHANGELOG.md, docs/PROGRESS.md를 실제 변경과 맞춰 갱신한다. 변경 파일·카탈로그 위치·테스트 결과·확인 못한 사항을 보고한다.
