# 난이도별 시드 기반 연구소 생성 구현 프롬프트

기존 LibGDX / Java 8 폐쇄 연구소 게임에 난이도별 랜덤 연구소 생성을 구현하라. 현재 쉬움 맵의 타일·벽·문·방별 가구 품질을 공통 기준으로 유지한다. 본 문서와 동봉 데이터는 목표와 참조 설계이며 실제 게임에서 적용/검증된 결과는 아니다.

## 1. 기존 코드 조사와 이번 범위

- 프로젝트 규칙, 실제 패키지, LaboratoryLayout/Room/RoomArea/Prop, WallAutotiler, Door/PlacementResolver, TileVisual/RoomVisuals, 외벽/내부 벽 렌더러, 가구 방향/footprint, 몬스터·루트 배치, 충돌·길찾기·미니맵·맵 전환·세이브를 실제로 읽는다.
- 현재 쉬움의 완성된 벽 연결/문 위치/북·남·좌·우 가구 렌더링 경로를 재사용한다. 난이도마다 다른 구식 렌더러를 호출하지 않는다. 쉬움에서 고친 벽이 보통/어려움에서 되돌아오면 안 된다.
- 이 단계는 생성·배치·검증·시드 재현과 기존 화면 연결이다. 새 보스/스킬/경제 밸런스 변경은 하지 않는다. 새 맵을 통짜 배경 이미지로 그리지 않는다.
- 동봉 JSON은 기존 타일/가구를 조립하기 위한 **데이터 에셋**이다. PNG를 가리키는 실제 TextureRegion ID는 포함하지 않는다. `asset_bindings.required.json`의 의미 ID를 실제 프로젝트 자산에 매핑해야 한다. 추정한 파일명/타일 인덱스를 하드코딩하지 않는다.

## 2. 생성 파이프라인과 책임

순서: 탐사 시드/난이도 선택 → 구조 틀/연결 그래프 → 방·복도 바닥 → 벽·접합부·문 → 방 테마/가구 → 캐비넷/드롭 공간 → 몬스터 → 최종 검증 → 불변 맵 스냅샷 공개.

- 생성기는 데이터를 만들고 렌더러는 읽어서 그린다. 렌더 프레임마다 난수로 타일/가구를 재선택하지 않는다. 엔티티 생성과 Texture 소유를 맵 모델에 섞지 않는다.
- 논리 바닥/벽/문 상태, 시각 타일, 실제 가구 바닥 footprint, 가려지는 위쪽 이미지 영역을 분리한다. 충돌·길찾기·미니맵은 같은 최종 논리 스냅샷을 사용한다.
- 순수 Java 생성/검증 모델과 LibGDX 자산/화면 연결을 나눈다. 실제 기존 클래스가 같은 책임을 갖고 있으면 확장하며 빈 추상 클래스와 거대한 Screen 분기를 남발하지 않는다.
- 맵에 `generatorVersion`, `templateVersion`, `difficulty`, `seed`(64비트 정수 문자열), `templateId`, `contentHash`를 기록한다. 재현 버그 보고에 모두 표시한다.

## 3. 구조 틀 12개와 입장 시 변화

- 난이도별4개, 총12개의 구조 틀을 사용한다. 동봉 layouts에는 압축 배치, 두 동 연결, 중정 순환, 엇갈린 배치의 서로 다른 roomSlots/선택 가능한 인접 연결이 있다.
- 초안 크기/방 수: 쉬움128×96·16방, 보통160×120·25방, 어려움192×144·36방이다. 실제 현재 쉬움의 좋은 방 크기와 맵 규모가 다르면 기존 기준으로 조정하고 난이도별 증가 관계를 유지한다. 숫자를 맞추려고 방을 빈 거대 공간으로 만들지 않는다.
- 방 셀은 단순 직사각형만 쓰지 않고 직사각형/모서리 후퇴/ㄱ자/짧은 돌출형의 검증된 폴리곤 중 선택한다. 동봉 참조는 직사각형과 모서리 후퇴형을 제공한다. 문 앵커를 잘라버리는 모양 변경은 금지한다.
- 연결 그래프는 모든 방을 잇는 spanning tree를 먼저 확보하고 짧은 우회 연결을 추가한다. 기존 방에 갈 수 있는 길을 무작위로 지우는 방식으로 다양화하지 않는다.
- 인접 방 사이의 짧은 복도를 우선한다. 긴 십자 복도 하나에 모든 방을 달지 않는다. corridor length/전체 통로 면적/막다른 구간 지표를 산출해 기존 쉬움의 품질 범위와 대조한다. 참조 팩의300개 검사 사례에서 인접 방 연결의 중심선 길이는 최대9타일이었다. 실제 게임 크기로 이식한 뒤에도 별도로 측정한다.
- 시드로 구조 틀, 선택 연결, 방 테마 분배, 방 크기의 허용 범위, 가구 패턴/슬롯 변형, 캐비넷, 몬스터를 바꾼다. 같은 시드+버전+난이도는 같은 결과다. 모든 입장에서 반드시 서로 다른 맵이라고 보장하지는 않는다. 최근 templateId 반복을 줄이는 선택 정책은 별도 데이터로 관리하고 재현 정보에 선택 결과를 기록한다.
- 의미 없는 거울 반전으로 가구 이미지까지 뒤집지 않는다. 논리 방을 회전/반전하더라도 각 벽에 맞는 전용 가구 뷰와 문 방향을 다시 선택한다. 해당 방향 자산이 없으면 지원되는 템플릿 변형으로 제한한다.

## 4. RNG 재현과 탐사 수명

- 전역 Random, 시스템 시간, 컬렉션 순회 순서에 의존하지 않는다. roomId/후보 좌표/종류는 정렬한 뒤 선택한다.
- topology/theme/furniture/loot/monster의 하위 시드 스트림을 분리한다. 바닥 장식 변형을 추가했더니 몬스터·아이템 배치가 전부 달라지는 구조를 피한다. 동봉 참조 검증기는 명시된 FNV-1a32 + XorShift32 규칙을 사용하며 Java 이식 시 unsigned shift/32비트 오버플로와 golden vector를 맞춘다.
- 새 탐사 확정 때만 새 시드를 만든다. 난이도 선택창을 열기만 하거나 창 크기 변경/일시정지/연구소 Screen 재생성으로 새 맵을 만들지 않는다.
- 진행 중 탐사를 복원할 때는 seed뿐 아니라 열린 문·열린 상자·꺼낸 물품·처치한 적 등 기존 세션 상태도 복원한다. 같은 시드 재생성만으로 이미 먹은 상자가 다시 채워지면 안 된다. 기존 세이브가 탐사 중단 복원을 지원하지 않으면 이번 단계에서 지원 범위를 명시하고 본부 영구 프로필은 보존한다.

## 5. 벽·문·대문

- 최종 바닥/방 경계를 만든 뒤 이웃 상태에서 직선·외/내 코너·T·십자·끝단을 결정한다. 방마다 임의 벽 이미지를 흩뿌리지 않는다. 기존 새 벽 스타일을 모든 난이도에 공통 적용한다.
- 한 칸 내부 벽과 외벽 링의 높이/두께/면 방향을 구분한다. 문은 실제 방 경계와 복도 연결부에 놓고 공중이나 방 한가운데 두지 않는다. 세로문은 전용 측면 뷰를 사용하며 정면 대문을90도 돌리지 않는다.
- 출입 대문은 본부↔연구소 전환의 동일한 출구 엔티티다. 연구소에는 귀환 대문 하나를 둔다. 시작 지점과 안전 접근 공간을 문 앞에 확보한다. 외관 이미지 크기와 실제 통과 영역은 분리한다.
- 닫힌 내부 문은 Space로 양쪽에서 열 수 있다. 닫혔다고 생성 검증에서 영구 벽으로 취급하지 않는다. 실제 문 앞에 도달해 여는 과정을 고려한 검증이 필요하다.
- 참조 데이터의1셀 문은 **논리 검증용 크기**다. 실제 게임 문 크기/앵커/충돌을 확인해 doorSocket을 맞추고 문 주변을 재검증한다. 작은 문 PNG를 무리하게 늘려3셀 문처럼 만들지 않는다.
- 바닥 없이 벽 투명부가 검게 뜨거나 모서리가 끊기는 기존 문제를 재발시키지 않는다. 현재 실제 렌더 경로에 연결된 타일 카탈로그를 사용한다.

## 6. 방 테마와 가구: 무작위 산포 금지

- 동봉 room_themes에는 입구/화학/생물/일반 실험/준비/표본/정보/CCTV/탕비/휴게/취침/화장실/탈의/샤워/기록/도서관16개 테마가 있다. 쉬움에도 다양한 방을 보장하고 보통/어려움은 테마 반복과 하위 구역을 늘린다.
- 기존 쉬움의 잘 배치된 방을 로컬 좌표의 배치 템플릿으로 추출한다. 그 템플릿을 최우선으로 사용하고 동봉 패턴은 확장/검증 참고로 적용한다.
- 북벽은 정면, 남벽은 뒷모습, 동/서벽은 해당 측면 자산을 사용한다. 이미지 회전/대각선 뷰/뒷모습 없는 가구의 앞모습 대체로 방향을 맞춘 척하지 않는다.
- wallSnap은 스프라이트 사각형이 아닌 실제 바닥 footprint의 뒷면을 논리 벽 안쪽 면에 맞춘다. 이미지 투명 여백 때문에 떠 보이지 않게 렌더 앵커와 충돌 앵커를 각각 조정한다.
- 큰 설비/벽 가구 → 중앙 작업대/침대 → 작은 소품 순서로 배치한다. 소품은 책상/선반의 부착 슬롯에 놓고 바닥에 무작위로 흩뿌리지 않는다. 같은 공간에 중복 collision을 쌓지 않는다.
- 문/대문 앞 접근 공간, 주 이동 통로, 방 진입 후 내부 활동 공간, 캐비넷 상호작용/드롭 공간을 먼저 예약한다. 예약 공간을 가구가 침범하지 않게 한다.
- 가구를 줄여서 빈 방으로 통과시키는 것을 기본 해결책으로 삼지 않는다. 충돌 발생 시 해당 배치 슬롯/패턴을 재선택하고 방별 최소 기능 가구 수와 최대 점유율을 확인한다. 참조의 footprint는 의미 역할별 검증용 근사치이며 실제 아트의 footprint로 반드시 재검증한다.
- 자산이 부족한 특정 역할은 실제 존재하는 같은 기능의 가구로 명시적으로 매핑하거나 그 템플릿 변형을 사용하지 않는다. 없는 PNG를 가짜 타일로 대체해 품질 검증을 통과시켰다고 보고하지 않는다.

## 7. 캐비넷·드롭

- 난이도 상승 시 전체 캐비넷 목표 수를 늘린다. 방 중앙만 쓰지 말고 벽면·구석·작업대 옆의 검증된 슬롯에 배치한다. 캐비넷은 실제 방향 뷰와 footprint를 사용한다.
- 캐비넷마다 접근 가능한 상호작용 위치1개 이상과 아이템이 떨어질 빈 위치를 예약한다. 좌표까지 갈 수 없는 캐비넷은 실패다. Space 안내는 현재 렌더 앵커 바로 위에 가깝게 띄우는 기존 규칙을 유지한다.
- 나무상자/일반·고급 캐비넷 개폐·연타·효과음·등급·추첨 가격/확률은 기존 루트 카탈로그를 사용한다. 생성용 난수와 개봉 추첨 난수를 분리하고 containerId를 안정적으로 만든다.
- 미리보기의 C는 컨테이너 논리 위치이며 새 PNG가 아니다. 참조 팩은 아이템 가격과 드롭 확률을 새로 정의하지 않는다.

## 8. 난이도별 몬스터

- 쉬움은 경비원·팀장을 제외한다. 슬라임/연구원 등 현재 허용된 낮은 체력 풀만 사용한다. 기존 쉬움의8배 증량이 이미 반영됐다면 다시8배 하지 않는다. 현재 검증된 쉬움 spawn 예산을 기준으로 보통·어려움의 총량과 밀도를 조정한다.
- 동봉 difficulty_profiles의 수량은 확정값이 아닌 초안이다. 실제 현재 쉬움 수량을 우선하고 normal/hard의 방 수·면적·총량·상한이 함께 증가하도록 설정한다. 몬스터 후보가 모자라면 벽/가구 안에 억지 배치하지 않는다.
- 보통·어려움에 경비원·팀장의 가중치를 높인다. 모든 몬스터를 고체력 몬스터로 바꾸지 말고 종류별 최소/최대와 예산을 둔다. 몬스터 HP·피해·추격 이탈 AI는 기존 동작을 보존한다.
- 팀장은 실제 방의 유효 내부 구석 후보에만 소환한다. 두 벽이 만나는 조건, 캐릭터 크기 여유, 문 앞 공간/가구/캐비넷 겹침, 플레이어 접근 가능성을 모두 검사한다. ㄱ자 방의 코너는 폴리곤 경계에서 계산한다.
- 유효 구석이 부족하면 다른 방의 후보를 시드 순서로 재선택하거나 팀장 목표를 명시적으로 줄인다. 팀장을 일반 중앙 후보로 몰래 대체하지 않는다. 생략/재시도 이유를 통계에 기록한다.
- 팀장 주변 달리기2회 분노 규칙과 기존 감지 반경/소음 누적 조건을 재사용한다. 구석 고정은 소환 위치 규칙이며 분노 후 추격을 막는 위치 고정이 아니다.
- 스폰/대문 주변은 안전 반경을 확보한다. 몬스터끼리 겹치지 않고 최소 거리와 플레이어와의 거리를 검증한다. 난수 while(true)로 무한 후보 추첨하지 않는다.

## 9. 접근성 검증과 실패 복구

- 방 그래프 연결 확인만으로 완료하지 않는다. 최종 벽/문/실제 가구 footprint가 적용된 actor 이동 그리드를 검사한다. 플레이어 AABB/반경을 반영하고 대각선 코너 끼워 통과를 허용하지 않는다.
- 모든 문을 열린 것으로만 보는 BFS 외에 **현재 도달 가능한 문 앞 → Space로 열 수 있는 문 개방 → 도달 영역 확장**을 반복하는 검증을 수행한다. 잠긴 특수 문은 기본 생성에 넣지 않거나 별도 열쇠 획득 가능성까지 검사한다.
- 대문 앞 스폰에서 모든 방의 활동 앵커, 모든 캐비넷의 상호작용 위치/드롭 슬롯, 대문 귀환 위치, 양방향 방문 접근 위치가 도달 가능해야 한다. 캐비넷 본체 셀은 solid여도 된다.
- 몬스터 위치를 정적 길막으로 넣어 맵 연결성을 실패시키지는 않는다. 다만 스폰 여유/겹침/구석 조건은 별도로 검사한다.
- 실패 시 실패한 가구/캐비넷 배치 슬롯부터 고치고 재검증한다. 그래도 실패하면 정해진 attempt 하위 시드로 최대3회 재생성한다. 최종 실패는 해당 난이도의 검증된 기본 틀로 폴백하고 fallbackUsed/원인/시드를 기록한다. 무한 재생성과 매번 다른 무작위 시드로 숨기기를 금지한다.
- 문 열림/가구 파괴 등 동적 장애물이 바뀌면 충돌·미니맵·귀환 길찾기 버전을 함께 갱신한다. H 귀환 경로는 닫혔지만 열 수 있는 문을 고려해 안내하고 도달하면 Space 안내를 제공한다. 발자국이 고체 가구를 관통하지 않게 한다.

## 10. 데이터 에셋·참조 도구 사용

- `data/layouts/`의12개 JSON, `room_themes.json`, `furniture_patterns.json`, `difficulty_profiles.json`, `asset_bindings.required.json`을 기존 맵 카탈로그에 연결한다.
- `tools/reference_generator.py`는 패키지의 추상 타일/근사 footprint를 검증하는 Python 참조 도구다. 게임에서 Python을 실행하지 않는다. 실제 Java 생성기를 구현할 때 데이터 포맷과 시드 규칙을 참고한다.
- `tools/validate_pack.py`는 여러 시드 생성, 재현 hash, 전체 방/문/캐비넷/대문 접근, 컨테이너/몬스터 목표, 쉬움 풀, 팀장 구석을 검사한다. 이 통과가 실제 PNG 앵커/플레이어 AABB/게임 실행 검증을 대신하지 않는다.
- `preview/` 이미지는 논리 평면도다. 장식 가구의 실제 게임 그림이나 완성 화면이라고 표현하지 않는다. 게임에 배경으로 넣지 않는다.

## 11. 프로젝트 검증·완료 보고
